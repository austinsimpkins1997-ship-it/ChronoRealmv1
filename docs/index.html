Every line knows where it came from.

kb turns folders of documents — PDFs, scans, zip archives — into a searchable database where every passage traces back to its file, its page, and a fingerprint of the exact bytes. Anything it can't read is still recorded, with the reason.

What happens to your files

  1. 1 Register

    Every file gets a row: path, size, and SHA-256 hash. Files inside zip archives too, plus empty, corrupt and macOS metadata files.

  2. 2 Extract

    Text comes out page by page from PDFs, and chunk by chunk from text and office files. Archives open with guards against unsafe paths and zip bombs.

  3. 3 Read the scans

    Pages with no usable text layer are OCR'd at 300 dpi, and each page keeps its confidence score. Results are cached, so rebuilds take minutes.

  4. 4 Index

    Two searches: ranked by relevance, and exact text with punctuation kept — for file numbers, citations and quotes.

  5. 5 Flag

    Low-confidence OCR, near-empty pages, duplicates and personal-data patterns are flagged for a human. Pattern counts only; values are never copied.

  6. 6 Verify

    Ten checks run against the finished database, and a warning fires if any file on disk changed since the build.

Your own notes live apart from the documents. Every annotation carries an author and an evidence label, so a summary — yours or a model's — never passes for the source.

Ten checks before you trust it

  • S0 The build finished
  • S1 Files on disk still match the database
  • S2 Every file has a final status
  • S3 Every archive entry is accounted for
  • S4 One record per PDF page, no gaps
  • S5 Search indexes match the stored text
  • S6 Every page that needed OCR got it
  • S7 Near-empty pages are flagged
  • S8 Extracted archive copies match their hashes
  • S9 The database passes SQLite's integrity check

First real run: a mixed archive of 104 sources — declassified PDFs, handwritten scans, nested zips — with 1,010 PDF pages. All ten checks passed.

Start with one folder

One Python file, standard library only. You'll also need poppler-utils and tesseract installed. A failed build never replaces a working database.

python3 kb.py --db knowledge.db build \
  --root docs=/path/to/documents
python3 kb.py --db knowledge.db verify
python3 kb.py --db knowledge.db search "query"
python3 kb.py --db knowledge.db search \
  --substring "56D-SF-4662117"

What it won't do

  • Read handwriting well. Heavily redacted or handwritten pages get flagged; check the page image there.
  • Tell you what's true. It shows where a line is, not whether the line is right.
  • Find names. The personal-data scan looks for patterns like phone numbers, not people.
  • Treat its markings as facts. Detected dates and classification lines are pattern matches.
